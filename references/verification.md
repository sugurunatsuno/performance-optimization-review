# 修正と検証の基準

## 変更前に残す情報

- 対象コードと入力条件: 対象の関数、データ量、値域、ランダムシード、スレッド数。
- 環境: 言語/バージョン、コンパイラまたはランタイム、最適化フラグ、CPU/GPU、OS、依存ライブラリ。
- ベースライン: テストの成否、メトリクス、計測回数。
- 意味論: 完全一致か数値許容誤差か、入力を変更してよいか、呼び出し順の制約があるか。

## 正しさのチェック

| 対象 | 確認するケース |
| --- | --- |
| 一般 | 空/最小/最大入力、繰り返し実行、意図しない変更、例外とエラーの順序 |
| 整数 | 0、負値、最大/最小値、型変換、オーバーフロー、ゼロ除算 |
| 浮動小数点 | ±0、NaN、±Inf、極小値/極大値、丸め誤差、相対誤差/絶対誤差 |
| 配列 | 非正方形、1 行/1 列、転置、連続/非連続、負ストライド、dtype/shape、broadcasting、境界外、エイリアシング、入力の破壊的変更 |
| SIMD | 端数要素、アラインメント、エイリアシング、スカラー版との差、SIMD 対応/非対応 CPU |
| 配置変更 | C/F order、SoA/AoS、変換費用、ビュー/所有権、キャッシュ/メモリ使用量 |
| 並列 | レース、再現性、同期、スケジューリング差、結果の集約順 |
| API | 出力内容と順序、破壊的変更、互換性、呼び出し回数に依存する副作用 |

許容誤差契約がある場合は、既存テストに準拠した比較方法を用い、最大誤差と必要なら ULP を記録する。基準がない場合に数値誤差を勝手に許容しない。

## ベンチマーク

- 同じ環境と負荷で baseline/candidate を比較する。コード変更と同時にコンパイラフラグや依存を変えない。
- 配列最適化では shape、dtype、strides、レイアウト、入力生成方法を固定する。連続/非連続、キャッシュ内/キャッシュ外、小/大のケースを分ける。
- 組み合わせ手法では serial / parallel-only / vector-only / combined を比較し、スレッド数とライブラリ内部スレッド数を記録する。変換/転送と一時配列のコストを含めた総時間も計測する。
- コンパイラの SIMD レポートやプロファイル結果を残す。コード上に SIMD 指示があるだけで実際にベクトル化されたとは断定しない。
- 実行順による偏りを小さくするため交互に実施する。可能ならウォームアップ後に 7～15 回計測し、中央値と分散を確認する。
- 入力は実務上の代表値を含める。キャッシュに収まる小入力だけで判断しない。
- 最適化で結果が使われない計算はコンパイラや JIT に削除されうる。計測対象の結果を検証かログで使い、計算が残っていることを確認する。
- CPU 使用率、サーマルスロットリング、バックグラウンド処理、JIT、GC、ページキャッシュ、I/O の揺らぎに留意する。
- baseline と candidate で同じ正しい結果が出ることを確認してから性能を採用する。
- ノイズと同等の差しかない場合は「有意な改善は未確認」と書く。統計的な有意差を根拠なく主張しない。
- コマンド単位の大きな処理は `scripts/benchmark_commands.py` を利用できる。短い関数にはプロジェクト標準のベンチマーク環境を使う。
- 関数単位の比較は、その関数だけを呼ぶ小さなドライバを用意し、`benchmark_commands.py` で変更前後のドライバを比較する。pytest-benchmark、cargo bench、go test -bench、BenchmarkDotNet などのベンチハーネスがあるプロジェクトでは、そちらを優先する。

使用例（`CLAUDE_SKILL_DIR` が無い環境では、このファイルのあるディレクトリの絶対パスに置き換える）:

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/benchmark_commands.py" \
  --baseline 'python3 app.py --mode before' \
  --candidate 'python3 app.py --mode after' \
  --warmup 2 --repeat 9 --verify-stdout
```

数値出力が `RESULT <case> <milliseconds> <integer-checksum>` 形式のときは `--verify-numeric-stdout --rtol ... --atol ...` を明示指定できる。名前/順序/整数checksumは厳密一致、時間値は正の有限数のみで許容誤差比較を行う。形式が異なる場合は利用できない。許容誤差は既存の数値契約に基づき決める。

`--verify-stdout` は標準出力だけを比較する。標準エラー出力の変化も契約の一部なら `--verify-stderr` を併用する。

このスクリプトは指定されたコマンドを繰り返し実行する。副作用のあるコマンド、ネットワーク呼び出し、書き込みや課金を伴う処理には使わない。実行前に対象コマンドを確認する。

## 報告テンプレート

```text
対象: path/to/file.ext:関数名
変更: 不変な係数計算をループ外へ移動
根拠: サンプルデータ 10^6 件で対象処理が CPU 時間の xx% を占有
正しさ: unit / integration / 境界値テストに成功
性能: baseline 中央値 x.xx ms → candidate 中央値 y.yy ms (z.z% 短縮、9 回、同一条件)
制約: 非連続配列と GPU は未計測
見送り: 逆数乗算は許容誤差契約がないため未適用
```

## 停止条件

- テストが壊れ、正しさを示せない。
- 性能改善が再現しない、あるいは遅くなる。
- 別の機能、外部依存、ビルド設定、公開 API に大きな変更が必要で、ユーザーの依頼範囲を超える。
- 既存の未コミット変更を安全に保護できない。

停止した場合は、該当箇所、理由、戻した変更、残った確認項目を記録する。
